# 현재 광고성과 PDF live 실패·개선 기록

같은 가상 PDF의 exact SHA를 사용했다. 민감정보와 원문 없이 순서·안전 오류 코드·변경만
기록한다.

| 순서 | 결과 | 관찰·변경 |
| ---: | --- | --- |
| 1 | 실패 | 최초 runner가 실패를 `UNEXPECTED_ERROR`로만 가려 단계 구분 불가 |
| 2 | 실패 | 안전한 예외 유형을 추가해 Solar 응답 후 `ValueError`임을 확인 |
| 3 | 실패 | 고정 원인 코드로 `SOURCE_EVIDENCE_NOT_ON_PAGE` 확인 |
| 4 | 실패 | 원문 그대로 복사하라는 교정 프롬프트와 1회 상한 재시도 후에도 같은 검증 실패 |
| 5 | 실패 | 원문·값 없이 `metric_key=likes`를 확인; 표 헤더와 값 결합 문제로 범위 확정 |
| 6 | 통과 | 두 번째에도 원문에 없는 개별 후보만 `NOT_FOUND`로 강등; 기대 안전 조건 10/10 |

총 외부 호출은 Document Parse 6회, Solar 9회다. 네트워크·HTTP 일시 오류가 아니라 모델이
표 헤더와 값을 합쳐 원문에 없는 `source_text`를 만든 문제였다. 라벨과 다른 숫자를 붙인
경우는 강등 대상이 아니며 계속 실패한다. 회귀 테스트는 다음을 고정한다.

- 외부 호출은 `--confirm-live` 없이는 시작되지 않는다.
- exact fixture SHA와 v3 10개 후보 집합이 다르면 live 실행 전 실패한다.
- 근거 실패 재시도는 최대 한 번이다.
- 두 번째에도 페이지 원문에 없는 개별 후보만 `NOT_FOUND`가 된다.
- 다른 지표 숫자, 통화·비율·기간 오인, 라벨 내부 부분 문자열은 계속 거부한다.
- 오류 출력과 로그에는 원문·키·원시 응답을 넣지 않는다.
