# 공개 조정 응답 E2E 체크리스트

이 문서는 대행사가 가입 없이 조정 요청 링크를 열고 조항별 응답을 한 번 제출하는 P0
흐름의 검증 절차를 기록한다. 공개 토큰·계약 전문·연락처·서명 링크는 테스트 기록에
남기지 않는다.

## 검증 범위

```text
소유자 조정 요청 발송
→ 공개 링크 조회
→ 열람 기록
→ 수락·거절·역제안 제출
→ 소유자 상세에서 응답·감사 이벤트 확인
```

## 자동 검증 결과

2026-07-31에 Python 3.12.13, `SUPABASE_MODE=mock` 환경에서 다음을 실행했다.

```bash
cd apps/api
.venv/bin/ruff check .
.venv/bin/pytest tests/test_adjustments.py tests/test_public_adjustments.py
```

결과:

- `ruff check .`: 통과
- 공개 조정 초안·발송 및 공개 응답 테스트: 9 passed
- 백엔드 전체 회귀 테스트: 181 passed
- 검증한 실패 경로: 항목 누락, 만료 토큰, 중복 제출, 두 번째 실제 발송

이는 mock Supabase 기반 API 검증 결과다. Supabase·Upstage·모두싸인 live 연동 성공을
의미하지 않는다.

## 브라우저 수동 검증

### 준비

1. FastAPI를 `SUPABASE_MODE=mock`으로 실행한다.
2. 소유자 흐름에서 조정 요청을 발송해 그 응답의 `public_url`을 얻는다.
3. 프론트엔드의 `.env.local`에 아래 값을 설정하고 개발 서버를 실행한다.

```dotenv
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
NEXT_PUBLIC_USE_MOCK=false
```

`public_url`의 토큰은 화면 공유·터미널 로그·이슈 댓글에 남기지 않는다.

### 정상 흐름

- [ ] 공개 링크를 연다. 계약 제목과 요청 조항만 보이며 소유자 연락처·내부 UUID는 보이지 않는다.
- [ ] **회원가입 없이 검토 시작**을 누른다. `/open` 호출 후 응답 화면으로 이동한다.
- [ ] 모든 조항에 응답한다. 거절에는 사유, 역제안에는 역제안 문구와 사유가 없으면 제출할 수 없다.
- [ ] 제출 중 버튼이 중복 실행되지 않는다.
- [ ] 성공 시 완료 화면으로 이동한다.
- [ ] 소유자 상세 API에서 응답, `RESPONDED` 상태, `ADJUSTMENT_OPENED`와
  `ADJUSTMENT_RESPONDED` 감사 이벤트를 확인한다.

### 실패 흐름

- [ ] 만료된 유효 토큰은 `410`과 만료 안내를 표시하고 요청 내용을 노출하지 않는다.
- [ ] 잘못된 토큰은 `404`로 처리하고 요청 내용을 노출하지 않는다.
- [ ] 이미 응답한 토큰을 다시 제출하면 `409` 오류를 표시하고 새 응답을 만들지 않는다.
- [ ] 공개 API 응답에 `Cache-Control: no-store`가 있다.

## 현재 제약

- 광고효과 기록·대조(6.14)는 P2 화면 목업이며, 그 외 P0 소유자·공개 화면은 실 API
  전환을 지원한다.
- 이 체크리스트의 기존 자동 결과는 mock 모드 기준이다. 실제 Supabase 프로젝트와 배포 URL이
  준비되면 같은 수동 절차를 다시 실행해 live 결과를 별도로 기록한다.
