# MVP 제품 범위

## 반드시 완성할 흐름

`계약서 업로드 → 조건 추출 → 근거 기반 검토 → 1회 조정 → 대행사 수정 계약서 업로드·대조 → 양측 전자서명 → 산출물 증빙 → 만료 확인`

## P0

- 소상공인 이메일·비밀번호 회원가입·로그인, 이메일 확인·비밀번호 재설정과 소유자 세션
- PDF 업로드와 핵심 조건 추출
- 사용자가 이해한 조건 5문항
- 기간·금액·해지·환불 불일치
- 빈칸·산출물·촬영 안전·책임 확인 신호
- 원문 페이지·문장·확신도가 연결된 조항 카드
- 원안 수용·절충안·요청안 문구
- 대행사의 수락·거절·역제안 1회
- 최대 4개 확정 조항과 수정 계약서의 근거 기반 대조·소상공인 최종 확인
- 모두싸인 상태와 중복 안전 웹훅
- 감사 타임라인, 산출물 한 건, 만료 일정, 최소 대시보드

## P2 광고효과 흐름

- 광고효과 기록과 대조(기획안 6.14)
- 대행사 리포트 업로드 → 지표 확인 → 계약 조건 대조 → 문의 문안 생성
- 리포트 업로드·영속 저장과 Upstage·Solar 지표 추출 API 구현됨
- 소상공인 확정값 저장·append-only 정정·계약 조건 대조·문의 문안·계약별 조회 API 구현됨
- 프론트엔드 월별 업로드·추출 근거 확인·확정·정정·집계·확인 신호·문의 문안 API 연동 구현됨
- 비식별 합성 PDF의 Upstage Document Parse·Solar Adapter live 연결은 검증됨
- 로컬 FastAPI 실제 TCP·live Supabase Auth/Storage/PostgreSQL·Upstage Parse·Solar를
  포함한 16.2~16.5 수직 E2E 통과, 합성 fixture 정리 확인
- 배포 FastAPI 환경의 수직 E2E는 배포 후 별도 검증

## 비목표

- 법률 자문 또는 사기·위법성 판정
- 실제 결제·송금
- 광고 성과·매출 기여도 자체 측정(대행사 리포트 기록·계약 조건 대조만 제공)
- 반복 자동 협상
- 다국어 UI
- 게시물 URL의 실제 존재 여부 자동 검증
