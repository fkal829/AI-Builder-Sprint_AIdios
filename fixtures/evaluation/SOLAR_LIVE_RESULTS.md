# Solar 검토 문구 live 연동 결과

2026-07-31에 고정 가상 계약 3건으로 Upstage Solar Chat API를 실제 호출했다.
실제 사업자 정보나 계약서는 사용하지 않았으며, 아래 내용은 원시 HTTP 응답이 아니라
Adapter의 보안 검사와 Pydantic 스키마를 통과한 필드만 기록한 결과다.

## 검증된 생성 문구

### 기간·총액 불일치

- 쉬운 설명: 총 계약금액이 사용자가 이해한 금액과 계약 원문에 기재된 금액이
  다릅니다.
- 원안 수용: 원문대로 총 계약금액을 3,600,000원으로 수용합니다.
- 절충: 양측이 합의한 금액을 명확히 명시해 주세요.
- 요청: 총 계약금액이 3,600,000원인지, 6,000,000원인지 확인해 주세요.
- 모델 한계: 입력된 계약문과 사용자의 이해 사이에 차이가 있으나, 실제 계약서의
  정확한 내용과 의도를 확인하기 위해서는 원본 계약서 검토가 필요합니다.

### 모호한 산출물

- 쉬운 설명: 산출물 수량에 '별도 협의'라는 문구가 있어 구체적인 기준이 명시되지
  않았습니다.
- 원안 수용: 산출물 수량은 별도 협의를 통해 결정한다는 문구를 그대로 수용합니다.
- 절충: 산출물 수량을 구체적인 범위(예: 최소·최대 수량)로 명시하거나, 협의 절차를
  계약서에 추가하도록 조정할 수 있습니다.
- 요청: 산출물 수량에 대한 구체적인 기준이나 협의 방식을 명시해 주시길 요청합니다.
- 모델 한계: 입력된 계약 내용만으로는 산출물 수량의 실제 적용 방식을 판단할 근거가
  부족합니다. 최종 확인은 계약 당사자와 법률 전문가의 검토가 필요합니다.

### 촬영 안전·손해 책임

- 쉬운 설명: 촬영 안전 책임 주체가 광고주로 명시되어 있으나, 책임의 구체적 범위와
  예외 사항을 확인해야 합니다.
- 원안 수용: 촬영 안전: 현장 안전에 관한 모든 책임은 광고주가 부담한다.
- 절충: 촬영 안전 책임은 광고주가 부담하되, 구체적 범위와 예외 사항은 별도 협의로
  정한다.
- 요청: 촬영 안전 책임의 구체적 범위와 예외 사항을 명시해 주시기 바랍니다.
- 모델 한계: 입력된 문구만으로는 책임의 구체적 범위와 예외 사항을 판단할 수 없으며,
  실제 계약서 전체와 관련 법규를 확인해야 합니다.

## 실패·재시도 기록

- 같은 3건을 한 요청에 담은 최초 live 배치는 설정된 120초 timeout 후 전송 오류
  재시도를 한 번 수행했지만, 두 번째 시도도 `ReadTimeout`으로 끝났다.
- 입력을 한 건씩 분리한 후 실제 요청 3회가 모두 성공했다. 따라서 endpoint·인증·
  strict JSON Schema 연동은 성공했지만, 3건 비스트리밍 배치는 현재 timeout 안에서
  안정적이라고 볼 수 없다.
- 자동 테스트는 `429` 응답 뒤 한 번 재시도하여 성공하는 경우, 전송 timeout을 한 번
  재시도한 뒤 `SolarReviewError`로 종료하는 경우, 잘못된 JSON과 스키마·ID·안전·
  입력 근거 검증 실패를 저장 전에 거부하는 경우를 검증한다.

## 재현 방법

실제 외부 호출과 비용이 발생한다. `apps/api/.env`에 `UPSTAGE_API_KEY`를 설정한 뒤
명시적인 확인 옵션으로 실행한다.

```bash
cd apps/api
.venv/bin/python -m evaluation.solar_live --confirm-live
.venv/bin/python -m pytest \
  tests/test_solar_adapter.py \
  tests/test_solar_live_evaluation.py -q
```

일반 `pytest`는 외부 Solar를 호출하지 않는다. live 결과는 모델 변경, 프롬프트 변경,
timeout 정책 변경 전후에 별도로 다시 실행해 기록한다.
